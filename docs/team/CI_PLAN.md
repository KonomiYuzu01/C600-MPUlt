# Deployed CI boundary

The workflow `.github/workflows/team-checks.yml` belongs in the actual Magic 600 Cell source repository. The desktop project is a local mirror and has no Git remote. The workflow uses its checked-out source with `source_root: "."`, never the private local mapping. Infrastructure and core jobs run on pull requests or explicit workflow dispatch after the workflow is committed and pushed; writing YAML locally does not activate GitHub Actions.

1. **Infrastructure job (Linux or Windows):** check out the team files; parse Agent TOML with the Python version required by the role configuration; compile Python runner syntax; parse PowerShell syntax on Windows; run `bash -n scripts/verify.sh` on Linux. Run `verify_team.py --stage infrastructure --source-root <checked-out-source>` only when a source checkout is available. Do not install an OpenAI API key for syntax checks.
2. **Core job:** separately check out the exact application ref, provision 64-bit Python and `requirements.txt`, then run `python scripts/verify_team.py --stage core --source-root <source> --allow-source-tests`. This is an ephemeral CI checkout, not the live development directory. Run `lifecycle` separately so failures retain their own scope and logs. Do not use continue-on-error to turn failures into green status.
3. **Native job:** do not add to unattended shared runners by default. Use an explicitly dispatched, dedicated Windows interactive environment with required licensed prerequisites and exclusive window ownership; run one chosen native stage with both opt-in flags. DirectX/native performance and G1/G2 acceptance still need the user's real environment and separate approval.

Always retain per-job exit status. Private logs may contain local paths and raw diagnostics; review/redact before uploading CI artifacts or using a public repository. Never upload sessions, global credentials, Managed DirectX DLLs or unreviewed screenshots. CI should not modify model assets, rebuild them automatically, publish releases or declare the entire 0.4 version complete.

No lint/typecheck configuration existed in the inspected application source; those remain `not configured`. The new workflow does not suppress failures. Core tests rely on bundled full-model assets and the retained oracle; a skeletal source checkout cannot stand in for the application. Offline controller tests do not use an API key. Do not add the personal key to repository variables or CI secrets for these jobs.
