# Native instrument scene — isolated P1 iteration

The user explicitly required a substantial redesign of the core graphical view, preserving the mathematical engine, state authority and manual solving. G1 and G2 remain separate pending approvals.

## Limiting interaction

The earlier native scene displayed independent, equally weighted cell thumbnails with a largely empty centre. It did not explain how the working block fits together. Permanent controls dominated the work, and bank switches rebuilt the entire onscreen keyboard. Reusing executed steps was also ambiguous. The accepted scope is a runnable interaction slice; a change of UI framework or renderer has not been proposed or performed.

## Decisions and rejection conditions

- Draw the union of the declared block and Target hosting cells in one fixed projection. A common vertex has one screen coordinate. Real shared faces, edges and vertices represent incidence only. They do not prove rigid piece movement, orientation or a setup sequence.
- Keep A/B preparation positions beside the main structure. Show canonical fixed P and actual I separately; Current and locked Next retain physical identity. Forecasts remain hollow, labelled with their boundary and independently selectable only through identity-safe routes.
- Use the retained cell palette and compact native controls. Put operation editing and catalogue access in on-demand regions. Context changes must preserve Current, Next, protection and the fixed scene unless the user changes the structural work context.
- Label macro-body effects separately from complete Prepare/Macro/Cleanup effects. Exact phase inspection is read-only and carries no permission to execute. Reject any presentation that implies otherwise or makes cycle arcs resemble an unlabelled protection boundary.
- After execution, retain the recipe visibly but require explicit New operation or Reuse steps before further draft editing/checking. Neither action chooses a macro, target, reference or setup. Every reuse needs fresh verification.
- A work-orbit switch must not release previously declared position protection. Check active and stored contexts, retain incompatible captures as distinct constraints, and expose the complete scope. An explicit release is required. Persistence and authoritative Session remain unchanged.
- Reuse existing keyboard controls when their structure is unchanged, updating their current canonical cap, command and hint data. A reused control must never execute a previously captured cap. Bank changes retain the physical-release barrier.

## Validation

Compare the same E1 synthetic two-insertion witness before/after at the same native dimensions. Inspect Actual and each finite boundary, hidden protection conflicts, explicit commit, New/Reuse, Next activation, undo/redo, compact keyboard, text focus and 1/2/5/20-cell work. Reject misleading geometry, inaccessible controls, stale action targets, lost protection or unsupported result claims. Record GDI control renders separately from desktop/DirectX output and physical-key or human trials.

The pure ordered-frame helper is a separate G1 mathematical experiment. It does not constitute an operational ordered-frame editor or approval. ## Keyboard in the graphical hub — 2026-09-15

The G2 keyboard is a persistent page of the same bottom work region as Operation. Only one page is visible at a time. Twenty Grip controls and seven Twist controls use the actual existing input router and current bank data. The uncaptured insertion bank remains explicitly uncaptured; no automatic cap assignment is introduced. Changing input phase does not replace the keyboard page. Selecting a macro is inspection; Add explicitly opens Operation. G1 retains its standalone keyboard entry.

Change key is an inline editor with action, bank/shared scope, original key, physical capture, exact conflict feedback, Apply and Cancel. It owns keyboard input while open and temporarily disables graph/orbit/catalogue selection; those objects remain visible. An editor capture must survive rejected page changes or save failures. Escape from any editor control cancels and returns focus to the graph. Closing or switching the work region clears held input and preserves drafts and identity bookmarks.

A source review identified direct step-editor entry during an outstanding append as a possible lost-work path. All entry routes now reject busy/executed/capture states; saving also compares the original phase recipe and full state hash. The direct busy-entry and stale-save cases passed in the final220112 Native workflow; final build provenance and narrower presentation retests are recorded in the keyboard review log.
