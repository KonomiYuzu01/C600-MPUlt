# Phase workspace redesign — bounded P1 slice

Baseline: native557166c3dc1f2353, adapter C1AAD6D6. Both user approvals Pending. The user rejected this UI and authorized redesign of its underlying solving/interaction logic, preserving useful work.

## Observed problem

The current display is an index-positioned state table with painted effects. It cannot show the state produced by manual Prepare before the chosen fixed macro. Every draft edit removes complete-result prediction. Bank activation also restores/clears work context. A user cannot continuously inspect preparation while retaining the problem and keyboard arrangement independently.

## Design and boundaries

1. Bank activation changes only input mappings. Explicit work-orbit selection restores the existing orbit context. Sibling A/B/I/M/E keys use the active keyboard bank's orbit. Show both scopes when different. No stored schema or canonical identity changes.
2. Add read-only inspection of an explicitly requested phase boundary: Actual, After Prepare, After Macro, After Cleanup. Expand only the user's finite draft. Compute exact labels and objects from the committed snapshot; never create another Session or commit permission. Empty phases are identity, not errors. This is draft inspection, not a protection certificate or staged native preview.
3. Inspect the same fixed work positions and identity bookmarks at each boundary, including chosen fixed macro support when supplied. Show slot-label correspondences and exact existing block predicates. Goal findings never choose a new target, macro or reference. A generic conjugating word must not be described as a certified geometric reference.
4. The Native hub provides stable selectable phase boundaries and carries the selected boundary's objects. Actual and forecast remain visibly different by label, solid/hollow treatment and preserved actual identities. Selecting a projected identity resolves its canonical identity; a projected position remains a fixed position. Role mutations still use explicit canonical objects and authoritative command validation.
5. Replace the fixed two-column presentation with an operation view that has selectable exact cycle relationships and a block view that shows declared requirements and actual topology. Maintain a compact Current/Next/protection context. Cell-color swatches alone do not claim geometry or orientation. The concrete graphical revision must be inspected after running, not accepted on a written design.

Alternatives: live-only preparation provides immediate state but cannot safely demonstrate temporary protected motion; full-review-after-each-key interrupts preparation and conflates inspection with applicability. A detached exact phase projection gives continuous inspection without either tradeoff. It introduces no alternate execution authority and uses the existing authenticated worker/lock/adoption path.

## Ownership and order

- Keyboard reviewer: adapter bank/orbit fix plus focused existing contracts; no native edits. Release adapter after checks.
- Solver reviewer: independent pure phase-inspection implementation/test file only after spec review, isolated model sessions; root integrates adapter route.
- Interaction reviewer: spec review, then ExperimentHub graphical/phase integration only under agreed payload; root owns Shell/Workspace/Tools and native whole-workflow fixture.
- Root: worker route, frontend request/adoption guards, command integration and serialized native builds/GUI. Reuse focused verification infrastructure; whole-model tests only if mathematical/persistent mechanics change.

## Falsifiable acceptance

- Cross-orbit bank choice preserves exact work intent, Next, review/pending, session labels; explicit orbit change restores only the user-chosen context.
- Phase projections match an independent primitive replay for nonempty Prepare/Macro/Cleanup and 1/2/5/20-cell objects; committed labels/journal/pending/protection never change.
- Fixed macro entry is inspected at After Prepare; a new target never retargets its raw recipe. Empty phases and orientation-only changes remain intelligible.
- Draft edits withdraw old projections immediately; late responses cannot overwrite newer context. Every displayed boundary names the phase and whether it is actual or forecast. Unknown protection remains unknown.
- Native G2 must let the user inspect and repeat a chosen preparation without reentering identity IDs or manually invoking the complete check after every turn. Test Current/Next and draft preservation across banks, views, cancel and explicit execution.
- Reject the graphical revision if its central area is still only a painted table, if meaningful actions require deciphering generic command lists, or if projected and committed state can be confused. Record actual rendering/input environment and limitations. No G1/G2 approval or production promotion follows from these checks.

This slice does not claim complete saved-method schema, ordered Grip frames, graphical automorphism reference or full endgame. Preserve these as requirements, not fake finished controls.
