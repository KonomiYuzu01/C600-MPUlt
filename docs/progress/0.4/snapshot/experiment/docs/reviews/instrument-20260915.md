# Native instrument iteration: decisions and evidence

Scope: isolated P1 interaction slice, preserving the retained WinForms/MPUlt renderer and authoritative Session. G1 and G2 are separately Pending. The user required a substantial core graphical redesign, not only new colors. No production integration or model identity changes were authorized or performed.

## Main workflow decisions

The limiting task was continuing a block after a finite manual operation. Independent cell thumbnails did not expose shared structure; execution left the old recipe looking reusable without a new decision; changing a keyboard bank could change the working orbit. A common block/Target hosting-cell projection and explicit operation lifecycle address these failures without replacing the rendering framework.

The shared scene shows actual incidence with one coordinate per shared vertex. A/B remain preparation regions. Fixed positions, actual identities, hollow forecasts, exact cycle arcs and protection use distinct representations. Hosting leaders identify a cell region, not a computed cut-piece centre, orientation proof or setup path. The operation strip and Macro Base are on demand. Current, locked Next and complete protection remain visible.

## Remaining limits

Actual sample8bbde56fee511a1c UIA revealed a startup-focus defect after the broader workflow passed: the orbit dropdown initially owned focus and the footer reported text input mode. Native focused baseline210158 reproduced it. The correction in dbce9848dd6a53de focuses the existing Keyboard button once before asynchronous Connect, only from the untouched default orbit control in the active main window. It does not focus anything when loading completes. Independent keyboard review preferred this over completion-time focus tracking because it eliminates that asynchronous focus race without adding state.

Four focused native runs passed21 assertions:210317 (default, held-key barrier, F5/F9 modal/router behavior and later filter adoption),210458 (open/close picker),210555 (search text) and210646 (another active window). All22 application source hashes match dbce9848dd6a53de. Later actual sample UIA verified the Keyboard button focused and the footer Work controls own the keyboard;33-I;draft/prepare after full model mapping. Direct router calls in the fixture are not physical F5/F9 evidence. The tests stimulate controls from a Shown handler, after the initial focus choice; they do not establish every possible pre-Shown input history or a controlled-delay timing benchmark. No such broader implementation was added.

The whole-window fixtures operate actual WinForms/MPUlt with real complete-model data and explicit synthetic legal witnesses. They are not human solving trials. GDI PNGs capture controls, not DirectX pixels. Actual screen: 1280×720, graphics DPI96. A requested 2560×1600 Form was clamped to1300×740; high-DPI and RTX4070 evidence is absent.

Native command-to-adopted-state timings still commonly take roughly0.6–1.2 seconds in these fixtures, including their polling. The keyboard-control-only median improved from398.7ms to30.2ms in its separate bounded fixture; this does not prove full input-to-correct-frame latency. End-to-end responsiveness remains a significant limitation.

Complete ordered-frame G1 capture, graphical reference manipulation, full worksheet input binding, required residual/endgame classes and broad P1 acceptance remain unfinished. The pure frame helper's exact action tests do not substitute for a usable native frame editor. Agent review and this interaction slice do not approve either gate.
