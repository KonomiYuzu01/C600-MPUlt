## Ownership and sequence

1. Geometry reviewer implements `reference_variants.py` and its tests. Explicit
   source/destination proper cell frames determine a geometric map. Verify full
   incidence and exact used-generator conjugation, emit actual legal chronological
   words, and compare the full transformed macro. Source frame is never guessed;
   geometry itself is not an executable setup. Existing legal-word conjugation
   remains distinct. Independent mathematical reviewer challenges this contract.
2. Mathematical reviewer implements `endgame_library.py`, audited invariant loading
   and their tests. Reuse current full-generator audit only when its actual bindings
   match. All35 placement/transfer/A/final-B applicability is explicitly catalogued;
   finite D5/A5 outcomes and collateral are checked. Parameters are user-selected,
   never matched automatically to a residual. Root reviews claims and coverage.
3. Continuity reviewer implements detached `workflow_continuity.py`, additive
   backwards-compatible atomic preference/event-context arguments to existing
   `Session.commit`, and tests. Existing SQLite meta records hold small optional
   receipts, not a second history DB. Root alone integrates adapter calls.
4. Root integrates position-only and exact requirements through the same block,
   protection, review and worksheet paths. Missing mode stays exact. Both modes can
   coexist conjunctively; removing exact protection is an explicit action. Source
   identity comes from all captured labels, never assumed to equal the position.
5. Root connects all services to existing Solve/Macro Base, canonical graphical
   inspection and editable command banks. Read-only review uses one ReviewContext.
   Endgame controls remain in Solve; residual stage suggestions do not overwrite
   explicit goals. Expose exact reference choices/variants, finite known family
   parameters, useful dynamic candidate evidence and journal-derived residual delta.
6. Integrate commit continuity only after matching preview/state/protection guards.
   Insert/Place false→true follows locked Next, otherwise the approved hosting-based
   block candidate. Other goals update residual suggestions without broadening
   automatic target changes. Completed orbit locks require exact labels/known frames
   and actual successful commit; New/reset/undo/redo/restore never synthesize one.
7. Rotate independent source reviewers after implementation, resolve concrete
   failures, and run affected bound tests. Run mandatory core/reference/crash tests
   for mechanics/persistence changes and native baseline before focused native UI.
   Focused native verification is required here; it does not replace next round's
   full continuous acceptance.

## Acceptance and failure conditions

- Each orbit has concrete legal witness and applicable residual-class coverage;
  trivial/C2/C5 final-B exclusions have current invariant evidence. D5/A5 retain
  actual group elements and complete collateral. No absence of candidate becomes
  a claim of mathematical impossibility or protection-safe reachability.
- Exact and position-only locks behave differently on genuine orientation-only
  action; Strict checks every actual primitive. Hidden objects remain checked.
- Explicit frame transforms preserve all canonical identities, original recipes
  and costs; new emitted words receive fresh Net/Strict checks. Stale/ambiguous
  reference choices fail without altering drafts or Session.
- Cross-orbit Next and return preserve drafts, chosen macro/reference, block and
  Local settings while positions update. Bank/focus changes are explicit. SQL
  failures leave state/preferences atomic, and recovery never retries a turn.
- Complete target/intent/score/residual/permission chain works through the existing
  native controls and keyboard; no file editing or raw-ID-only endgame parameter UI.
- Final verification receipts identify exact inputs. Unsupported paths or native
  behavior stay explicit blockers until fixed; no declared feature count suffices.
