# Clipboard restoration diagnosis (2026-09-17)

The native 012546 run passed its mathematical copy/editor assertions and failed while restoring the original clipboard with HRESULT 0x800401D0. The captured pre-test clipboard was STA and unlocked. No restore-time holder metadata was captured, so the historical holding process and exact OleSetClipboard/OleFlushClipboard stage remain unknown. Microsoft documents this HRESULT as failure to open the Windows clipboard, not as proof that a format was invalid.

A metadata-only read found the currently available clipboard had one String format and no COM value; this is not evidence about the earlier run's payload. A second STA held the clipboard for 2300 ms. The old synchronous SetDataObject(saved, true) reproduced the exact HRESULT (red.log, exit 1), then the diagnostic restored and compared every original format in memory. No clipboard contents or format names were logged.

The test-only fix snapshots supported values eagerly into a separate DataObject, refuses unavailable/unsupported values before the first test write, and yields the STA pump between retries of only this open-clipboard HRESULT. Restore success requires the full original format set to be present and every original value to match. Strings/arrays/streams are compared exactly; bitmaps by dimensions and pixel content. Empty is explicitly verified. The deadline is 10 seconds; failure remains a failing test and is combined with any earlier test failure. This does not make permanent contention recoverable, and it does not restore clipboard data that was already lost before this task began.

Actual isolated verification: green3/result.json, exit 0, 4.766 s including compilation, tested source hashes unchanged. The controlled 2300 ms hold needed 19 retries; timer events continued on the same STA. Synthetic text, HTML, binary stream, byte array, image and file list survived another clipboard value and restoration. A deliberately shorter deadline produced a real failure; the retained backup restored after the holder released. Empty and unsupported-data refusal were checked. The original clipboard captured at probe start was restored and verified at exit.

Green1/2 failed the diagnostic's initial PNG-byte equality for a synthetic bitmap; PNG encoding/native GDI representation is not pixel identity. Green3 uses an opaque native bitmap fixture and exact ARGB pixel equality. These failed probes also restored the original clipboard. No full application native run is claimed here; root will rebuild the included MathematicalNameNativeChecks.cs and run its actual copy/editor path.
